# 清楚叙述与完整证据的报告写作规则

## 目录

1. 主路径与深度层
2. 三分钟摘要
3. 心智模型与必要定义
4. 方法、理论或系统解释
5. 证据分析
6. 深度完整性契约
7. 去重与篇幅
8. 按论文类型适配

## 1. 主路径与深度层

同一份 Markdown 同时服务两类阅读：

- 主路径回答“它研究什么、核心思路是什么、结论由什么支持、可信吗”。
- 附录回答“完整证据、数学/算法/实现细节和外部证据在哪里”。

不要把附录密度复制到正文。正文中每个图、表、公式、定理、证明链或协议都必须改变读者对核心思路或结论的理解。分层的目的只是控制阅读顺序，不是缩小研究覆盖范围。

## 2. 三分钟摘要

摘要必须在报告最前面，覆盖：

1. 问题：研究对象、现有知识或方法缺口，以及为什么值得解决。
2. 核心思路：方法论文给最小例子和信息流；理论论文给假设—定理—结论链；系统/数据论文给接口、协议或数据流。
3. 结论与证据：只保留最改变判断的中心结论及证据。实验论文给绝对值、基线和差值；理论论文给中心定理与关键前提；系统/数据论文给核心测试、覆盖或审计结果。
4. 判断：价值、最大证据、最大缺口。
5. 路线：不同阅读目标该看哪些章节。

摘要中避免首次出现未解释的缩写。无法避免时，在同一句给出含义。

## 3. 心智模型与必要定义

选择一个能贯穿全文的最小问题、具体例子、toy case、反例或形式化对象。它要能承载研究目标、关键约束和成立/成功条件。纯理论论文若举例反而失真，可以直接建立最小定义系统。任何例子都不能替代准确的问题定义、命题或算法流程。

术语、定义与符号表只保留首次理解后文所必需的项目，不设数量配额。每项只写：

- 一句话定义；
- 它在本文中控制什么。

不要把常识性 AI 词汇全部收进术语表。

## 4. 方法、理论或系统解释

方法论文按因果顺序解释，不按论文 section 顺序机械改写：

```text
输入是什么
→ 中间状态如何变化
→ 哪个机制是新东西
→ 输出如何形成
→ 训练时学什么
→ 推理时能看到什么
```

理论论文按依赖顺序解释：

```text
研究对象与定义
→ 关键假设
→ 引理或中间命题
→ 中心定理
→ 证明中决定结论的步骤
→ 反例与适用边界
```

系统、平台、数据集或 benchmark 论文按接口和协议顺序解释：输入与数据语义 → 处理流程 → 接口/协议 → 输出与指标 → 实现依赖 → 失败和公平性边界。

先讲描述，再讲评价。读者尚未理解某个模块前，不要连续讨论它的假设、消融和失败。

公式解释先回答“为什么需要”，再给例子和公式。所有承载新机制、关键训练信号或理论结论的公式都必须在正文或附录 B 解释。系统、平台和 benchmark 论文可以没有正文公式；不得把报告自己的形式化包装成作者公式。

## 5. 证据分析

先从 Abstract、Introduction/Contributions 和 Conclusion 建立核心 Claim 清单，再用 Claim—Evidence—Verdict 表作为唯一判断索引。每条核心 Claim 必须有原文 section / table / figure / equation / theorem / appendix 或代码路径。正文证据部分按以下顺序：

1. 论文最重要的 Claim；
2. 与论文类型匹配的直接证据；
3. 最强替代解释、反例、可比基线或前置假设；
4. 证明、对照、协议或比较是否足以排除替代解释；
5. 证据支持到什么强度；
6. 还缺什么证据。

任何表格、定理、证明链、反例、系统测试或数据统计之后都必须写解释，但不要逐项复述。优先解释：

- 哪条证据最直接支持或削弱 Claim；
- 哪个差异、前提或证明步骤最不稳健；
- 哪个结果、边界情形或实现语义与论文叙述不一致；
- 证据究竟支持到什么范围，不能外推到哪里。

正文可以精简证据，但附录 A 必须保留所有承载核心结论的完整实验表、证明依赖、反例、协议、数据统计、系统测试、代码路径或其他可核对转录。若原文没有某类证据，明确写“原文未提供/不适用”及其判断影响，不能用空白章节代替。

## 6. 深度完整性契约

最终报告必须满足以下覆盖要求：

1. **Claim 完整性**：覆盖全部核心贡献、中心定理、核心性能结论和关键因果归因；数量由原文决定，一条中心 Claim 也可以构成完整短论文。
2. **核心思路完整性**：方法论文交代输入、输出、状态变化、核心机制、训练信号和实现依赖；理论论文交代定义、假设、定理、证明依赖、反例和适用边界；系统/数据论文交代接口、协议、数据语义和公平性；综述/观点论文交代范围、材料选择、综合或论证链及反方观点。
3. **证据完整性**：正文解释决定判断的证据；附录 A 收录所有支撑核心 Claim 的实验、证明、定理依赖、反例、数据统计、系统测试、代码路径或失败案例。
4. **关键细节完整性**：正文解释决定机制或结论的公式、定理、算法、协议或复杂度；附录 B 保存必要推导、符号、算法步骤、数据/检索协议和工程映射。原文无相关内容时不自行制造。
5. **文献完整性**：`review` / `reproduce` 按判断需要核对真正相关的工作，不设统一数量；正文实际引用的来源全部进入附录 C 并给出直接链接。没有使用外部文献时明确说明原因。
6. **复现或验证完整性**：方法/系统论文说明数据、权重、代码、配置、资源和阻断项；理论论文说明证明前提、可机械核验部分、反例搜索与关键缺失引理；数据论文说明获取、许可、划分和评测协议。
7. **定位完整性**：第 3 章每个 Claim 都在附录 D 有一条独立定位，不能只写笼统的“见正文/实验章节”。

如果原文确实没有某类内容，使用“原文未提供/不适用 + 因此不能判断什么”的显式声明。缺失或不适用声明算完整审计，空白或静默省略不算。

## 7. 去重与篇幅

一个问题只完整出现一次：

- Claim 的证据问题写在第 3 章；
- 最终判断只引用 Claim ID 并汇总影响；
- 附录只补完整证据和审计细节，不重复正文解释。

正文通常为 10,000–18,000 字符，仅作为可读性提示。复杂论文可以超过；不要为了命中数字删除独立证据。超过时优先按以下顺序下沉：

1. 完整宽表；
2. 次要公式；
3. 代码逐文件核查；
4. 文献逐篇介绍；
5. 不改变结论的通用局限。

附录不设总长度上限。下沉意味着移动到同一报告的附录并保留正文指针，不是删除。正文较短不自动代表清晰；如果 Claim、核心思路或决定性证据覆盖不完整，应先补全再谈压缩。

不要通过大量小标题制造“清晰感”。同一因果链优先保持在一个小节内。

## 8. 按论文类型适配

### 理论论文

- 主路径强调假设—定理—结论链。
- 证明细节进入附录；正文保留决定结论的步骤。
- 正文公式数量由证明链决定；非决定性推导放附录。
- 证据载体是定义、假设、引理、定理、证明、反例和复杂度，不要求图片、实验表或多条 Claim。

### 方法论文

- 主路径强调表示、目标函数、模块和 baseline 的本质差异。
- 解释所有承载新机制或关键训练信号的公式；非关键标准公式放附录。
- 证据载体通常是机制对照、主结果、消融、泛化和代码语义。

### 系统 / 平台 / 数据集 / benchmark

- 主路径强调任务定义、数据覆盖、评测协议、信息泄漏、公平性和实际实现。
- 公式不是质量指标；原文没有决定性公式时正文可以为 0 个。
- 证据载体通常是接口/协议、数据覆盖、系统测试、吞吐/成本、泄漏、公平性和失败案例；图片按信息价值使用，不设数量配额。

### 实证论文

- 主路径强调研究问题、对照、统计、稳健性和外推。
- 优先表格与效应量，不为满足格式解释通用公式。
- 证据载体是研究问题、对照、效应量、统计不确定性、稳健性与外推边界。

### 综述 / meta-analysis / 观点论文

- 综述和 meta-analysis 强调范围、检索与纳入标准、材料覆盖、质量评估、综合方法和异质性；证据载体是来源清单、选择流程、编码/统计协议和遗漏审查。
- 观点或立场论文强调前提—论据—结论链、最强反方观点、反例和适用边界；不能把修辞强度当作证据强度。
- 没有原创实验、代码、图片或公式时不补造，但所有中心论断仍须有原文定位和证据责任。
