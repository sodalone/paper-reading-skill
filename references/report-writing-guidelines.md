# 理解优先的报告写作规则

## 目录

1. 主路径与深度层
2. 三分钟摘要
3. 直觉与术语
4. 方法解释
5. 实验证据
6. 去重与篇幅
7. 按论文类型适配

## 1. 主路径与深度层

同一份 Markdown 同时服务两类阅读：

- 主路径回答“它解决什么、怎么做、结果怎样、可信吗”。
- 附录回答“完整数值、数学细节、代码差异、外部证据在哪里”。

不要把附录密度复制到正文。正文中每个图、表、公式都必须改变读者对方法或结论的理解。

## 2. 三分钟摘要

摘要必须在报告最前面，覆盖：

1. 问题：具体失败场景和现有方法缺口。
2. 方法：一个例子和 3–5 步信息流。
3. 结果：2–4 个绝对值、基线和差值。
4. 判断：价值、最大证据、最大缺口。
5. 路线：不同阅读目标该看哪些章节。

摘要中避免首次出现未解释的缩写。无法避免时，在同一句给出含义。

## 3. 直觉与术语

选择一个贯穿全文的具体例子。例子要能同时承载任务输入、方法决策、输出和失败模式。

术语表限制为 5–10 项，每项只写：

- 一句话定义；
- 它在本文中控制什么。

不要把常识性 AI 词汇全部收进术语表。

## 4. 方法解释

按因果顺序解释，不按论文 section 顺序机械改写：

```text
输入是什么
→ 中间状态如何变化
→ 哪个机制是新东西
→ 输出如何形成
→ 训练时学什么
→ 推理时能看到什么
```

先讲描述，再讲评价。读者尚未理解某个模块前，不要连续讨论它的假设、消融和失败。

公式解释先回答“为什么需要”，再给例子和公式。系统、平台和 benchmark 论文可以没有正文公式。

## 5. 实验证据

以 Claim—Evidence—Verdict 表作为唯一判断索引；每条 Claim 必须有原文 section / table / figure / equation 或代码路径。正文实验部分按以下顺序：

1. 论文最重要的 Claim；
2. 对应实验与数值；
3. 与最强可比基线的差值；
4. 对照是否公平；
5. 证据支持到什么强度；
6. 还缺什么实验。

主表后必须写解释，但不要逐行复述所有数字。优先解释：

- 哪个变化最大；
- 哪个差异可能不稳健；
- 哪个结果与论文叙述不一致；
- 绝对水平是否仍然很低。

## 6. 去重与篇幅

一个问题只完整出现一次：

- Claim 的证据问题写在第 3 章；
- 最终判断只引用 Claim ID 并汇总影响；
- 附录只补数据，不重复正文解释。

正文目标 8,000–14,000 字符。超过时按以下顺序下沉：

1. 完整宽表；
2. 次要公式；
3. 代码逐文件核查；
4. 文献逐篇介绍；
5. 不改变结论的通用局限。

不要通过大量小标题制造“清晰感”。同一因果链优先保持在一个小节内。

## 7. 按论文类型适配

### 理论论文

- 主路径强调假设—定理—结论链。
- 证明细节进入附录；正文保留决定结论的步骤。
- 允许 2–5 个正文公式。

### 方法论文

- 主路径强调表示、目标函数、模块和 baseline 的本质差异。
- 正文通常 1–3 个公式。

### 系统 / 平台 / 数据集 / benchmark

- 主路径强调任务定义、数据覆盖、评测协议、信息泄漏、公平性和实际实现。
- 公式不是质量指标；正文允许 0–2 个。

### 实证论文

- 主路径强调研究问题、对照、统计、稳健性和外推。
- 优先表格与效应量，不为满足格式解释通用公式。
